# New API 二开版本

本仓库是基于 [QuantumNous/new-api](https://github.com/QuantumNous/new-api) 的 fork 二开版本，用于在原有 New API 能力基础上维护自定义功能。

## Fork 基线

- Fork 仓库：[Doryyang17/new-api](https://github.com/Doryyang17/new-api)
- 上游仓库：[QuantumNous/new-api](https://github.com/QuantumNous/new-api)
- 原始二开基线：`12fc0100`（`Bump Electron lockfile dependencies`，`v1.0.0-rc.15-22-g12fc0100`）
- 最近上游同步目标：`bee45b58a`（本轮拉取的 `upstream/main`）
- 本次同步前已保护 fork 独有提交：53 个（包含二开、修复、文档和历史合并）
- 本轮上游同步来源：`2d8e50bf3..bee45b58a`，共 69 个上游提交

### 本轮上游更新摘要

本轮将上游 `main` 的 69 个提交通过 merge 合入，保留 fork 的全部 53 个独有提交、二开行为和中文单语策略。上游主要更新包括：

- 异步任务统一迁移到沙箱 JavaScript 插件，支持插件管理、原生路由、模型别名、OpenAI Video / Responses 协议和更完整的轮询状态；任务先持久化再结算，插入失败时退还预扣。
- 统一登录验证、账户绑定、密码修改、账户删除与访问令牌安全校验；新增独立安全设置页和审计日志，Telegram 接入统一 OAuth 流程。
- 重构模型、供应商和价格管理，完善任务用量表达式、工具转换、推理参数及模型 `@` 修饰符与规范计费模型身份；增加 GPT-6 Astra 内置表达式价格、阿里 Wan 3.0 等支持。
- 用量日志增加普通用户、管理员、root 分层元数据，并完善 Token、额度操作及任务产物展示；模型健康条返回按小时成功率。
- 改进 SQLite WAL / 锁等待、PostgreSQL 连接池兼容、历史约束迁移和重复建表行为；中继新增等待上游响应头的超时配置。
- 同步前端安全表单、抽屉交互、初始化引导、缓存、模型定价卡片及构建依赖更新。

本轮二开适配重点：注册码及严格 Turnstile 校验接入统一认证；插件路由继续执行宵禁、每日额度和提示词检查；任务持久化同时关联签到赠金预扣账本，防止进程退出后的孤儿恢复误退款，并保存等级计费快照；日志保留二开的赠金拆分、风控详情和按需加载；正常价格优先展示与测活固定费继续生效。

### 升级兼容说明

- 当前上游仅支持 64 位架构。MySQL / PostgreSQL 的 `users.quota`、`used_quota`、`aff_quota`、`aff_history` 需要 64 位整数列；启动检查发现旧 32 位字段时会拒绝启动，需要在部署前备份并完成数据库迁移。SQLite 不执行这项列宽检查。
- 单请求计费继续使用饱和保护；充值仍保留本 fork 创建订单时冻结到账额度的约定，结算同时校验钱包上限。
- 安全相关设置入口迁至独立「安全设置」页面；个人资料页继续展示签到赠金和消费型用户等级。
- 本轮是源码合并，不代表生产数据库迁移、镜像发布或部署验收。

## 定制化功能

### 服务端公告中心

将原有前端公告升级为带服务端状态的公告中心，提供稳定的发布、阅读和运营统计链路。

功能行为：

- 公告支持标题、摘要、正文、分类、普通 / 重要 / 紧急等级、置顶、发布时间、下线时间、立即展示和强制阅读配置；未到发布时间或已经下线的公告不会继续作为有效公告展示。
- 登录用户拥有独立已读回执和未读数量；公告列表、顶部通知入口与独立公告页共享服务端状态，跨设备登录后仍能保持一致。
- 强制阅读公告通过专用弹窗按发布时间顺序展示，用户确认阅读后才进入下一条；加载期间不会把尚未取得的强制公告误判为已处理。
- 管理后台支持可视化编辑、发布状态判断、阅读人数、未读人数、阅读率及未读用户清单，便于运营跟进重要公告触达。
- 未登录首页继续使用公开公告预览接口；正文、个人已读状态和管理员统计分别使用不同接口，避免把用户阅读数据暴露到公开入口。

### 系统可用时间

新增「系统可用时间」功能，用于配置服务不可用时间段。当前默认目标场景为 `22:00-08:00` 宵禁窗口。

功能行为：

- 管理后台新增「定制化功能」菜单，并在该菜单下提供「系统可用时间」配置。
- 支持配置是否启用、不可用开始时间、不可用结束时间、判定时区和提示文案。
- 宵禁状态下，主页展示替换为宵禁提示页，导航栏和站内其他页面仍保持可访问。
- 宵禁状态下，模型调用类 API 直接返回终止型 `403` 和 `system_curfew` 错误，不再进入渠道分发，也不会调用上游渠道 API；避免 Codex 等按 `5xx` 规则重试的 Agent 将其当作临时服务故障。
- 宵禁拒绝会写入错误日志，保留请求路径、时间窗口、时区、Token 上下文等审计信息。
- 触发日志支持回查关联用户，便于运营侧定位受影响账号。
- 当前单一前端补充浅色、深色主题下的主页展示。

### 渠道可用时间

新增渠道级每日可用时间配置，复用 New API 原生渠道启用、手动禁用状态，不引入独立的渠道分发开关。

功能行为：

- 渠道管理行菜单新增「可用时间」，支持独立配置开关、开始时间、结束时间和判定时区；默认值为 `08:00-12:00`、`Asia/Shanghai`，并支持跨午夜时段。
- 可用时间按 `[开始时间, 结束时间)` 判定。到达开始边界时自动启用渠道，到达结束边界后自动禁用渠道；保存配置后立即按当前时间同步一次状态。
- 夏令时跳时导致配置边界不存在时，边界落在跳变后的第一个有效瞬间；回拨导致边界重复时，开始取第一次、结束取第二次，确保同一天保持一个连续可用窗口。
- 后端启动时立即对账，并以 15 秒周期持续检查。时间窗外即使人工启用也会再次禁用；时间窗内发生的人工禁用或原生自动禁用会保留到下一次开放边界，避免调度器覆盖当班故障处置。
- 关闭定时配置只停止后续调度，不改变渠道当时的启用或禁用状态。
- 渠道列表同时展示原生状态和可用时段；当前页存在启用中的定时配置，或启用/禁用状态筛选生效时，按调度周期轻量刷新，确保跨边界后筛选结果能够自动增删渠道。
- 调度状态变更继续走原生渠道状态更新、原因记录和渠道缓存刷新链路，多密钥渠道的密钥级状态不受影响；全部密钥均不可用时，开放边界仍保持原生自动禁用状态，不会加入路由池。

### 模型广场服务可用率

模型性能指标会排除已识别的用户请求错误和用户主动取消；渠道、网络、上游服务错误以及无法确认来源的错误仍按失败统计。渠道状态码映射只影响客户端响应，不改变内部错误归因。

### 每日系统用量上限

新增「每日系统用量上限」功能，用于给整站或指定模型配置每天可消耗的额度上限。

功能行为：

- 管理后台「定制化功能」下新增每日系统用量配置，支持全站开关、全站额度、多个模型独立额度和提示文案。
- 模型调用类 API 在进入渠道分发前检查当日系统用量；全站超限时拒绝所有模型，模型独立额度超限时只拒绝对应模型，不再调用上游渠道 API。
- 用量统计以消费日志为最终来源，按规范化模型名聚合，并提供 5 分钟级别的缓存快照，兼顾严格拦截与管理页展示性能。
- 排行榜页面展示全站及模型独立额度的当日用量概览，方便运营侧观察已用额度、剩余额度和限制状态。
- 全站或模型独立额度超限统一返回终止型 `403`，并携带稳定错误码和禁止重试标记，避免客户端将其当作临时限流继续请求。
- 模型独立额度使用自身配置的提示文案，不再错误复用全站额度提示。
- 限制检查失败时采用保守策略，避免统计异常时绕过整站额度上限。

### 消费型用户等级

新增基于用户原生累计消耗额度的等级体系，用于按真实模型消费进度提供可领取等级和计费折扣。

功能行为：

- 等级进度只读取 New API 原生 `users.used_quota`，不重复维护第二套消费账本；充值、签到赠金和异步任务状态本身不会直接增加等级进度。
- 管理后台「计费设置」支持启用等级功能，并配置等级名称、说明、门槛、计费倍率、徽标颜色和停止发放状态；基础等级固定为门槛 `0`、倍率 `1`。
- 等级门槛严格递增，越高等级的计费倍率不能高于前一等级；已保存等级不能删除或重排，只能停止后续发放，避免破坏用户与领取历史。
- 用户达到门槛后在个人资料页手动领取当前可达的最高等级；领取过程使用事务与行锁，等级字段、领取记录和用户缓存保持一致。
- 用户等级倍率叠加在原生分组计费链路中，并在请求开始时形成快照；使用日志保存等级 ID、名称、倍率和徽标信息，便于后续核账与配置变更追溯。
- 个人资料页展示当前等级、下一等级、进度、剩余消耗额度和可领取状态；用户列表、模型价格、API Key 分组及使用日志统一使用稳定的等级 / 倍率展示格式。
- 管理配置使用 revision 做乐观并发保护，多个管理员同时修改时拒绝旧版本覆盖；关闭功能后现有等级归属仍保留，但计费倍率回退为 `1`。

### 每日签到与签到赠金

新增可切换的每日签到奖励模式：管理员可以选择发放普通余额，或发放当日有效的独立签到赠金；两种奖励不会同时发放。

功能行为：

- 管理后台「定制化功能」下提供签到配置，与提示词检查、系统可用时间等二开能力统一收纳；定制化功能菜单使用站点图标并位于设置导航末尾。
- 签到赠金是独立余额类型，不并入用户当前余额；个人资料页和钱包页复用同一数据接口与展示组件，单独显示赠金余额和剩余有效时间。
- 模型调用优先消耗仍在有效期内的签到赠金，不足部分再由用户选择的钱包或订阅额度承担；完整消费金额仍计入使用日志、用户用量、渠道用量、排行榜和数据看板。
- 使用日志展示完整扣减金额，并用紧凑的「赠」图标标记包含赠金的记录；详情中保留赠金与钱包 / 订阅的实际拆分，便于运营核账。
- 赠金与钱包 / 订阅的预扣、结算和退款使用同一请求账本及数据库事务，避免请求失败、异步任务重算或违规费扣减时只更新其中一种余额。
- 运行进程通过实例租约维护未结算预扣；仅当归属进程租约超时后才自动恢复孤儿预扣，滚动重启期间不会误退仍由旧进程处理的请求。
- 赠金在次日零点失效；过期后的失败退款只恢复审计余额并保持过期状态，不会让已过期赠金重新参与消费。

### 登录注册安全改造

新增登录与注册安全改造，用于降低自动化注册、无效注册码撞库和 OAuth 自动建号风险。

功能行为：

- 接入 Cloudflare Turnstile 免费验证方案，登录、密码注册和 OAuth 首次注册补码等关键入口使用严格校验。
- 前端在 Turnstile 未加载、加载超时、验证失败或未完成时给出明确提示，避免用户只看到按钮不可用。
- 新增「注册码注册」开关；开启后，密码注册、OAuth 首次建号和 WeChat 首次建号都必须提供有效注册码。
- 注册码支持后台批量生成，格式固定为 20 位 `A-Z0-9` 随机字符；单个注册码只能被一个用户消费一次。
- 注册码管理页支持查看未使用和已使用清单、展示数量、全量复制、10 条分页；已使用清单展示 `user_id` 与用户名。
- OAuth 已有绑定账号保持原有直接登录；首次 OAuth 登录完成授权后进入专门的注册码补充页，补码成功后才创建账号。
- OAuth 待注册资料使用服务端 pending ticket 与过期时间保存，不把完整 OAuth 资料写入浏览器 cookie session。
- 无效注册码失败会进入轻量风控：连续 3 次失败临时封禁 1 小时，24 小时内累计 10 次失败封禁 24 小时；风控维度使用 HMAC 后的 IP 与浏览器指纹，支持 Redis，Redis 不可用时回退到内存。
- 当前改造不依赖邮件系统；邮件验证仍保持原有独立开关和流程。

### 提示词过滤与二次审核

新增提示词过滤系统，用于在请求进入上游渠道前完成本地合规检查和可选二次审核。

功能行为：

- 模型调用类 API 在渠道分发前读取请求体并执行提示词过滤，拦截命中规则的请求，不再调用上游渠道 API。
- 支持 `block`、`warn`、`monitor` 三种处理模式；`block` 返回可配置 4xx 状态码和稳定错误码，`warn` / `monitor` 通过响应头标记命中结果并继续请求。
- 支持内置规则、自定义正则规则、敏感词、分组白名单、渠道白名单、扫描长度上限、阻断提示文案和命中日志开关。
- 超长 Prompt 按头尾片段扫描，避免处理大型类二进制载荷时拖慢请求链路。
- 命中日志会保存脱敏后的预览、规则命中、命中词、分数、动作、请求路径和 Token 上下文，便于后续审计。
- 管理员排查入口可查看、复制和下载管理员专用完整文本；普通用户日志接口继续移除完整文本和 `admin_info`，避免敏感内容越权暴露。
- 提示词过滤返回 460 等拦截响应后，前端仍能保留并展示本次请求历史，避免用户只看到空状态。
- 日志详情视图支持查看提示词过滤的规则、动作、命中词和上下文摘要。
- 可配置兼容 moderation 接口的二次审核服务，支持自定义 base URL、模型、超时时间和 API Key；二次审核默认 fail-closed，审核失败时保持保守拦截。
- 前端在「定制化功能 / 提示词检查」页面提供总览、触发日志、规则集、自定义规则和词库文件管理入口。

### 提示词过滤词库管理

新增可运营的提示词过滤词库能力，用于维护大量敏感词和启用预置词库。

功能行为：

- 支持上传 `.txt` 词库文件，按文件内容计算 SHA-256，生成稳定词库 ID，并限制单文件大小与最大词条数。
- 支持词库启用/停用、名称、分类、权重和严格命中标记调整。
- 支持预览词库内容、在线更新词条、删除自定义上传词库。
- 内置 3 个精简预置词库（涉政、色情、暴力），由 Konsheng Sensitive-lexicon 来源素材审计合并而来；旧全量 Konsheng 文件已从预置词库中移除，不再随运行时预设提供或生效。
- 预置词库默认禁用，管理员可按需预览、编辑和启用副本。
- 词库命中统一进入提示词过滤评分与日志链路，和内置规则、自定义规则共用同一套阻断、告警、监控策略。

### 充值额度统计与结算安全

新增用户累计充值额度统计，并统一加固不同支付渠道的到账结算流程。

功能行为：

- 充值订单新增冻结后的到账额度字段，在创建外部支付订单前完成额度换算和边界校验，避免付款后因配置变化或数值异常导致到账不一致。
- 易支付、Stripe、Creem、Waffo、Waffo Pancake 和管理员补单共用事务化结算逻辑，重复回调不会重复增加用户余额。
- 启动时为历史成功订单补齐可确认的到账额度，无法安全换算的异常记录保留后台告警，不会静默写入错误额度。
- 管理员用户详情新增「累计充值额度」，与当前余额、已用额度分开显示，方便运营核对用户真实充值贡献。
- 额度换算继续使用统一的饱和保护，异常超大值会被拒绝并记录，而不是发生整数溢出或负向记账。

### 批量测活与并发防护

新增轻量级请求行为检测，用于降低模型批量测活、快速轮询和无意义扫描对渠道及系统资源的消耗。

功能行为：

- 根据用户、Token 和可信客户端 IP 的短时请求量，结合模型快速轮询及重复内容等行为进行风险评分；业务失败、上游异常和失败后重试不参与评分。
- 重复内容属于辅助信号，只有风险分达到阈值且同时命中请求量极高或模型轮询等强异常因子时才会拦截；同模型重复发送相同提示词不会单独触发限制。
- 对 `hi`、`hello`、`ping`、`test`、`你是谁` 等精确无意义短文本只增加单项风险分，不会仅凭一次正常短问题直接拦截。
- 批量测活和在途并发分别支持观察和拦截模式；观察模式只记录管理员诊断日志，拦截模式对真实异常请求返回 `429` 和 `Retry-After`。
- 风险处置只使用短时冷却及用户、Token、IP 临时限制，不执行永久封禁；已限制请求会在读取大请求体前直接拒绝。
- 增加用户级和 Token 级在途并发上限，覆盖普通、流式和 Realtime 请求；超限不排队，Redis 环境支持多节点统一计数和长连接租约续期。
- 管理后台「安全与限制 / 批量测活与并发防护」提供开关、模式、冷却时间、并发上限、日志开关和分组白名单配置；功能默认关闭，建议先观察后拦截。
- 基于 IP 的检测只有在显式配置 `TRUSTED_PROXIES` 后才启用，避免伪造转发头造成误封；多节点部署建议配置 Redis。

### 短请求测活惩罚与模型定价展示

支持通过 `tiered_expr` 对短输入请求收取固定费用，同时在模型广场向用户展示正常业务档位的 Token 单价。

功能与运维约束：

- 模型广场优先展示表达式中 label 为 `normal` 的输入、输出和缓存读取价格；未配置 `normal` 时，回退到首个包含 Token 单价的档位。分组倍率继续作用于展示价格。
- 固定常数档会在分档表中按「固定费 / 次」展示；实际请求命中 `测活请求` 档时，使用日志费用旁显示红底白字「异」标识，并以日志中的 `matched_tier` 作为判定依据。
- 管理后台打开无法安全转换为可视化表单的复杂表达式时，会自动进入源码模式并保留完整原文；仅查看或尝试切换模式不会生成 `p * 0 + c * 0` 覆盖草稿。
- 调整正常价格时，应修改 `billing_setting.billing_expr` 中 `normal` 档的 `p` / `c` / `cr` 系数；只修改 `ModelRatio`、`CompletionRatio` 或 `CacheRatio` 不会改变已启用 `tiered_expr` 模型的实际结算。
- 调整测活规则时，在源码模式修改 `len < N` 和固定常数。v1 表达式中固定美元金额换算为 `美元 * 1_000_000`，例如 `$0.2` 对应 `200000`。
- 批量改价前应备份 `options` 表中的 `billing_setting.billing_mode` 与 `billing_setting.billing_expr`；保存前通过编辑器右侧预览确认将写入的 mode / expr，保存后分别核对模型广场 `normal` 价格和使用日志 `matched_tier`。

### 中文化维护策略

本 fork 将前后端文案维护范围收敛为中文，减少多语言同步成本。

功能行为：

### 额度授予审计与计费预检

新增可追溯的额度授予与请求风险审计，并继续加固请求进入计费链路前的边界检查。

功能行为：

- 额度授予使用独立批次与明细记录，保留来源、数量、领取与结算状态，避免重复发放或丢失审计链路。
- 目标用户支持按关键词、角色、状态、当前余额和余额区间筛选；Root 用户始终排除，最终发放只以管理员明确勾选的用户清单为准。
- 充值和模型使用行为可以共享北京时间自然日或自定义日期范围；支持筛选范围内有无充值、有无模型消耗，以及按多个规范化模型名进行“任一命中”筛选。
- 支持选择当前筛选结果，并在授予批次中保存筛选快照和可读摘要，方便后续还原本次运营圈选条件。
- 用户列表按当前筛选范围展示最近使用和消耗数据；大范围结果受目标数量上限保护，避免误操作全量发放。
- 请求风险检测结果写入管理员可见日志详情，保留触发因子与处置信息，同时继续隔离普通用户不可见的内部审计字段。
- 计费预检覆盖用户控制的数量、时长和最大 Token 等乘数边界，异常输入在进入预扣费前终止，避免整数溢出或负向记账。
- 预扣、结算、退款与签到赠金拆分继续共用请求账本，失败路径保持可恢复和可核对。

### 使用日志查询优化

围绕大规模使用日志列表、筛选和详情查看，降低重复计数、超大字段传输和深分页带来的数据库压力。

功能行为：

- 使用日志列表支持稳定游标分页和紧凑投影，列表阶段不再无条件携带管理员完整提示词等大字段；需要查看时通过独立详情接口按稳定定位信息加载。
- 总数与额度统计按相同筛选条件独立执行，前端复用统计结果并减少列表翻页时的重复查询。
- SQLite、MySQL、PostgreSQL 和 ClickHouse 分别维护兼容的查询与索引路径；ClickHouse 使用稳定行标识支持同秒日志分页和详情定位。
- 前端统一筛选参数、分页游标和详情缓存，保留请求 ID、上游请求 ID、用户、Token、模型、渠道、分组与时间范围等现有筛选能力。

日常二开以 `main` 作为唯一长期维护分支，验收后直接提交并推送 `origin/main`。临时开发或上游合并保护分支只用于短期回退，确认代码已进入 `main` 后应及时删除。

- 系统可用时间：后端强制拦截、前端主页替换、管理后台配置入口、宵禁日志用户展示。
